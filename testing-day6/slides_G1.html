concetto

status code: di chi è il problema

2xxè andato bene200 · 201
4xxha sbagliato il client400 · 401 · 403 · 404 · 409
5xxha sbagliato il server500 · 503
Se un input sbagliato produce un 500, è un bug del server.

lab 1

il contratto pubblico

def test_health():
    # Act
    risposta = requests.get(f"{BASE_URL}/api/health", timeout=5)

    # Assert
    assert risposta.status_code == 200
    assert risposta.json()["status"] == "ok"
  • ogni chiamata di rete ha un timeout
  • lo schema JSON si valida con jsonschema
  • per mandare JSON rotto apposta: data=, non json=

concetto

fixture

# tests/conftest.py
@pytest.fixture
def token(base_url):
    r = requests.post(f"{base_url}/api/login", json={...}, timeout=5)
    return r.json()["token"]

@pytest.fixture
def auth(token):                         # una fixture può usarne un'altra
    return {"Authorization": f"Bearer {token}"}

# tests/test_carrello.py
def test_carrello(base_url, auth):       # pytest le passa in base al nome
    r = requests.get(f"{base_url}/api/carrello", headers=auth, timeout=5)

In pratica: l'Arrange scritto una volta sola, invece che in ogni test.
